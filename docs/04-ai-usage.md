# 04 AI 辅助使用说明

## 用户提供的内容

用户提供了《考核规则.md》《项目要求.md》，确认按建议的核心链路方案开始，并提供本地模型接入配置。用户原始要求是验收依据，不由生成代码反向定义要求。

本地密钥只用于获授权的模型调用，不写入文档、运行 Trace 或仓库交付内容。此处不复制密钥值。

## AI 协助范围

本次由 AI 助手协助完成方案拆解、Python 代码、合成资料、提示词、测试、评估脚本和项目文档。开发阶段分工检查了本地工具、模型接口、验收逻辑及证据边界；这种开发协作不代表产品采用多 Agent 架构，交付应用只有一个模型决策循环。

主要生成及修改内容包括：

- CLI 入口、真实模型适配器与离线 Mock。
- 模型动作分发、执行预算、历史输入和引用校验。
- 合成的制度/FAQ、冲突语料、修改后语料及测试场景。
- 单元测试、真实/Mock 批量验收、运行记录保存。
- 失败分析及提示、校验和检索规则的修订。
- README 与需求、方案、评估、AI 使用、复盘文档。

## 实际校验与修改方式

不是仅接受 AI 输出的文字说明：执行了代码、检索样例、单元测试及真实模型调用，并保存实际输出。最新结果与运行版本由评估文档统一登记，不能把 Mock 流程测试写成真实模型决策效果。

开发过程中针对发现的问题做了具体修改，例如：拒绝空白引用；区分未恢复工具故障与正常资料不足；移除完整验收问题的整句映射；增加动作外层结构示例和预算提醒；保留首轮格式失败记录后使用新目录复测。

## 个人贡献的披露边界

不能因为代码存在就声称用户亲手编写或逐行修改了这些代码。本记录只确认用户提供要求、确认方案及本地接入配置，AI 完成协助实现与验证；没有证据证明的用户个人代码修改、独立学习收获或手动测试，不在文档中编造。

正式面试或提交时，建议由提交者亲自运行项目、解释关键模块、审阅引用和冲突行为，并如实补充自己的修改记录。尚未发生的个人复核不能提前写成已完成。

## 使用约束

- 只提交简短、可审计的动作依据，不要求模型内部思维过程。
- 合成制度不代表任何真实公司的规则。
- 外部模型实际支持情况以运行记录为准。
- AI 生成的结论仍须核验，尤其是引用是否语义支持答案以及冲突是否被擅自裁决。

## 第二次全面审查的AI辅助

本轮仍由AI分工审查和实现：独立代码回归、要求到证据审计、新产品用例设计、逐项真实输出复核。用户提出全面审查请求并已配置本地模型；没有虚构用户亲自修改代码、运行测试或掌握全部实现。发现的缺陷、假阴性、失败运行和修订均见06-audit.md。
