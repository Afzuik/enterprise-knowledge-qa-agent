# 05 实施复盘与下一步

本文件记录实施中观察到的问题和工程修订，不代替提交者的个人学习陈述。实际用时、最新通过情况和最终剩余项由评估文档及最终交付记录补充。

## 难点一：流程可运行不等于真实模型能稳定完成

离线规则 Mock 可以稳定走完预设场景，但真实模型还需要持续遵守动作结构，并在资料不足时及时停止。首轮真实验收在 T03 和 T09 出现失败，Trace 可见连续 `invalid_model_output`，最后触及 `step_limit`。T03 还先进行了多轮无结果检索。

证据保留在：

- `examples/live-v1/T03/trace.jsonl` 和对应输出。
- `examples/live-v1/T09/trace.jsonl` 和对应输出。
- `examples/live-v1/summary.json`。

这些记录说明格式稳定性与停止策略是实际问题，不能因为工具、接口成功运行就宣称任务全部成功。首轮脱敏错误未保存完整无效模型输出，因此仅凭旧 Trace 不能逐条断定错误 JSON 的具体形式。

针对观察到的问题，当前实现补充了 `finish` 完整外层动作示例、每轮预算提醒、格式修复提示，以及无相关资料时避免无意义穷举的约束。修改后使用 `live-v2` 新目录复测，不覆盖首轮失败。复测完成后，第二轮固定验收10/10通过、共38次决策且无格式错误；全部运行绑定同一源码摘要。详见03-evaluation.md和live-review.md，不外推生产可靠性。

## 难点二：引用“在原文中”仍可能不可靠

仅检查 `quote in text` 会接受空字符串，空白字符也不能视为有效证据；当前校验要求引用各字段为非空文本，再检查本轮读取来源、版本与子串关系，并添加相应测试。

即使引用存在，也不保证它支持答案的语义。当前不把子串检查宣传成事实核验器，仍需要核对答案断言与原文，特别是数字、范围、否定和冲突情形。

## 难点三：失败恢复需要按对象记录

资料为空与工具故障必须区分。某一次读取失败后，另一个片段读取成功，不能简单清除全部失败状态；否则系统可能错误报告“没有资料”。当前循环按工具及读取对象记录未恢复错误，避免无关成功掩盖失败，并保留 `incomplete` 状态与错误原因。

## 难点四：避免为固定验收样例背题

初始检索归一化含完整改写问题映射，独立检查后删除，改用通用短语与字符二元组。另发现“申请”这样的通用动词会把资料外问题误召回到请假流程，因此加入通用停用词，同时保留请假主题正例检查。

新增了不同措辞的报销问题、资料外申请问题和主题正例。这些小样本只能说明具体回归检查，不能支持“检索泛化能力显著提升”的结论。未来应划分调参集与留出集，比较召回指标和冲突双文档召回率。

## 本轮可归纳的工程经验

- 真实模型模式必须早验证；Mock 是测试工具，不是能力证明。
- 状态和失败语义与正常回答同样重要，尤其要区分“资料不足”和“未能取得资料”。
- Trace 应保留动作与观察的关系，失败版本也有复核价值。
- 更强提示不能代替参数、引用和预算校验；反过来，格式校验也不能代替语义判断。
- 版本日期不能自动推导制度优先级，召回分数不能自动推导制度权威性。

以上是从实施证据归纳的经验，不宣称用户已经独立掌握或亲自完成全部修订。

## 后续优先级

1. 最新真实运行已完成逐项复核；后续扩大样本并重复运行，持续检查冲突裁决与引用语义支持。
2. 增加独立改写、长文档、多片段、显式适用范围和替代关系等样本；不要只重复 D01/D02 数字冲突。
3. 比较基线词法检索与改进方案，用未参与调参的问题报告召回及失败类型。
4. 在真实业务接入前补足权限、数据治理、审计、提示注入评估与部署隔离；这些不属于当前原型已完成能力。
5. 正式提交前由用户复跑、记录真实个人修改、确认题号和评审访问权限，提供 GitHub URL 与最终 commit SHA。
